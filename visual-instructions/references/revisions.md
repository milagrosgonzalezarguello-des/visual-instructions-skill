# Correction rounds

A manual is finished over several rounds: the author corrects figure by figure, then the client or a reviewer sends changes. Handle each round so that nobody has to send the same correction twice.

## 1. Do what was asked

Apply the change as requested. If the client names something differently from the document ("Historial de archivos cargados" where the manual says "Historial de Archivos"), use the client's wording in the place they asked for it. Do not silently "fix" their request to match your earlier choices - that is how a second round of corrections starts.

If a request is unclear or contradicts something in the product, apply the most literal reading and say so in your summary. Do not stall the round on a question you can flag.

## 2. Find where else it impacts

A correction is rarely about one place. Before closing the round, search the whole document for the same thing:

- **A replaced capture** - every other figure built from the old capture (the same screen cropped differently, instruction cards drawn on it, zoomed details). Replace them all, so the reader does not meet two versions of one screen.
- **A changed word or name** - every other occurrence: body text, figure cards, captions, alt texts, table of contents, quick reference, cross-references.
- **A changed behaviour** ("REFRESCAR clears the filters") - every other screen with the same control, and any note or tip that assumed the old behaviour.
- **A removed or added section** - numbering, links and the table of contents.
- **A new field or button visible in a new capture** - the steps and cards that list the fields.

Then:

- Apply the ones that are plainly the same correction (the same capture, the same control doing the same thing).
- **Suggest** the ones that are a judgement call - for example renaming the screen everywhere after the client used a different name once. Say what you would change and where, and let the author decide.

## 3. Say what could not be updated

When a new capture does not show something an existing figure needs (the menu, a button only another role has, the bottom of a table), keep the old figure and report it: which figure, what is missing, and what capture would fix it. A reader noticing two different-looking screens is better warned about than discovered by the client.

## 4. Check roles and views

Look at each new capture for signs it was taken with another role or state than the reader's: an "Admin" badge, extra filters, missing buttons, a different user name. Use it if that is what was asked, sanitize it like any other, and flag the mismatch.

## 5. Report the round

Close with a short summary, in this order:

1. What was changed, per request, with the final wording.
2. Where else you applied it.
3. Suggestions you did not apply, each with its place.
4. What could not be updated and what is needed.
5. What you verified in the render and what you did not.

Then save the lesson: if a correction reveals a rule (a term the client insists on, a behaviour you had wrong), apply it to the rest of the document now and keep it for the next one.
